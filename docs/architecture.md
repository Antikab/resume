# Архитектура резюме

Проект решает две задачи: показывает интерактивное портфолио и формирует документы для отклика. У них общий источник фактов, но разный состав представления. HTML документа и PDF используют одну вёрстку.

```text
src/content/ + src/config/
  ├─ presentation/resumeView.js → Vue-компоненты → сайт
  └─ document/createResumeDocument.js
       ├─ renderText.js → TXT
       └─ renderHtml.js + resume-document.css → HTML
                                                 └─ Playwright / Chromium → PDF
```

## Границы модулей

- `content` — обычные ESM-объекты: факты, периоды, описания проектов, контакты и ссылки. Импортируется напрямую и браузером, и Node; не зависит от SVG, Vue, DOM или файловой системы.
- `config` — подписи разделов и пути готовых документов. Не хранит вторую копию резюме.
- `presentation` — адаптер для сайта. Добавляет иконки, цвета и начальное состояние раскрытия по стабильным ID. Исходные объекты не изменяет.
- `components` и `layouts` — отображение данных через props. Состояние раскрытия остаётся локальным в компоненте опыта и связано с ID проекта, а не индексом в массиве.
- `document` — чистые преобразования. `createResumeDocument` задаёт состав и последовательность типизированных через JSDoc блоков. HTML- и TXT-рендереры ничего не читают и не записывают. HTML экранирует текст; достижения оформляются настоящими списками.
- `scripts` — побочные эффекты: чтение CSS, запись файлов, проверка дипломов и PDF, запуск браузера. Скрипты не используют Vite для чтения контента. Vite участвует только в сайте и его браузерной проверке.
- `public` — файлы, доступные посетителю. Генерация происходит при разработке, в браузере посетителя ничего не пересчитывается.

Отдельные DTO, API-слой, глобальное хранилище и runtime-схемы каждого локального объекта здесь не нужны: внешнего API нет. Проверяются реальные границы — наличие и сигнатура файлов, структура прочитанного манифеста, обязательный текст документа. При появлении внешнего источника данных ему потребуется отдельный адаптер с проверкой ответа.

## Актуальность PDF

`resume:pdf` собирает самостоятельный HTML, печатает его и записывает PDF через временный файл с последующим переименованием. После успешного экспорта сохраняется манифест:

- SHA-256 итогового HTML, включая CSS;
- SHA-256 кода PDF-рендерера;
- версия установленного Playwright;
- SHA-256 самого PDF.

`build` воспроизводит HTML и проверяет все поля. Это обнаруживает изменение данных, стилей, настроек печати, версии библиотеки или повреждение PDF. Если запись манифеста не завершилась, сборка отклонит несогласованные файлы. Не обновляйте хеши вручную: пересоздавайте документ командой `yarn resume:pdf`.

Системные шрифты и явно выбранный канал браузера не входят в манифест. Он обеспечивает согласованность исходников и сохранённого файла, но не заменяет визуальную проверку после смены окружения. Chromium нужен только для экспорта и браузерных проверок.

## Правила изменений

1. Меняйте факт один раз в `content`. Четыре рабочих проекта связаны с текущим опытом с явным пояснением продолжения работы из ГлавАПУ.
2. Сохраняйте ID существующих элементов: от них зависят иконки, ключи Vue и доступность раскрывающихся блоков.
3. Не помещайте HTML в тексты и не импортируйте SVG в `content` или `document`.
4. Меняйте печатную вёрстку только в `document`; PDF получает её автоматически. Правила `break-inside` удерживают описание проекта на одной странице, пока блок помещается в A4.
5. После изменения содержания пересоздавайте документы, запускайте проверки и просматривайте PDF. Рост объёма текста может увеличить число страниц — универсально фиксировать две страницы без потери читаемости нельзя.

Структура не требует изменения стека или полного переписывания компонентов. Существующие CSS-классы сохранены, чтобы организационные изменения не затронули дизайн.
